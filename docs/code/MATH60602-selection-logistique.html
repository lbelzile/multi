Sélection de modèle - régression logistique

On considère la sélection de variable et la pénalisation dans le cadre de la régression logistique. Les mêmes impératifs existent que précédemment, soit le risque de surajustement et la nécessité de valider la performance avec des données de réserve (échantillon/entraînement vs validation vs test), et potentiellement de le faire plusieurs fois si nous avons plusieurs critères à optimiser.

Le modèle de régression logistique est estimé par maximum de vraisemblance; il n’y a pas de solution explicite pour les estimations. Cela rend l’estimation plus coûteuse, mais les critères d’information restent disponible. Chaque variable explicative ajoutée au modèle améliorera la vraisemblance des données d’entraînement, donc il est nécessaire de pénaliser ou de considérer la performance sur les données gardées en réserve, potentiellement via validation croisée. Le LASSO se généralise aussi de la même manière.

Si on veut choisir un modèle optimal, on peut prendre celui qui maximise un critère (score propre) sur des données de validation. Pour des données \(\boldsymbol{y} = (y_1, \ldots, y_n)\) avec \(y_i \in \{0,1\}\), c’est le cas du score de Brier (ici positivement orienté) \[S(\boldsymbol{y}, \boldsymbol{p}) = -\sum_{i=1}^n (y_i - p_i)^2\] ou du score logarithmique \[S(\boldsymbol{y}, \boldsymbol{p}) = \sum_{i=1}^n \{\log p_i y_i + \log(1-p_i)(1-y_i)\}.\] Le code ci-dessous cherche (selon une recherche séquentielle, exhaustive, ou via un algorithme génétique) le modèle avec le plus petit BIC — l’utilisation de la pénalisation cela nous évite de refaire une séparation de l’échantillon. Par la suite, on fait le calcul du point de coupure optimal (par validation croisée), et on obtient la classification.

En principe, il faudrait regarder la performance en faisant une autre validation, mais cela impliquerait nécessairement une validation croisée imbriquée dans une autre. Nous regardons donc la performance directement sur les 100K données tests, en calculant le profit (revenus moins dépenses) pour notre envoi d’échantillon promotionnel.

La première partie du code charge les paquets R, divise les bases de données en échantillons d’apprentissage et de validation et définit la formule du modèle avec toutes les interactions et les termes quadratiques.

On peut ensuite procéder à l’ajustement des différents modèles: celui avec toutes les variables de bases, l’autres avec les 105 coefficients qui mène à un surajustement, ici lié à la quasi-séparation de variables.

Pour chaque modèle, on répète les étapes suivantes

  • ajustement ou sélection du modèle avec pénalisation BIC
  • calcul du point de coupure optimal avec notre matrice de gain
  • classification des données test
  • estimation du profit
# Modèle avec toutes les variables principales
base <- glm(yachat ~ ., data = appr, family = binomial)
# Calcul du point de coupe optimal
#  (par validation croisée)
base_coupe <- hecmulti::select_pcoupe(
  modele = base,
  c00 = 0,
  c01 = 0,
  c10 = -10,
  c11 = 57
)
# Performance sur données de validation
base_pred <-
  predict(object = base, newdata = valid, type = "response") > base_coupe$optim
base_perfo <-
  -10 * sum(base_pred) + sum(valid_ymontant[base_pred], na.rm = TRUE)

Pour le LASSO, la fonction hecmulti::select_pcoupe n’est pas adaptée. On démontre plutôt comment calculer le profit avec les prédictions individuelles des montants d’achats, pondérés par la probabilité d’achat suite à l’envoi d’un échantillon par publipostage.

# Calcul avec LASSO

formule <-
  formula(
    ~ (x1 + x2 + x3 + x4 + x5 + x6 + x7 + x8 + x9 + x10)^2 +
      I(x2^2) +
      I(x6^2) +
      I(x7^2) +
      I(x8^2) +
      I(x9^2) +
      I(x10^2)
  )

xmat_train_lm <- model.matrix(
  formule,
  data = dbm |>
    dplyr::filter(test == 0, !is.na(ymontant))
)[, -1]
y_train_lm <- with(dbm, na.omit(ymontant[test == 0]))

xmat_train_log <- model.matrix(
  formule,
  data = dbm |>
    dplyr::filter(test == 0)
)[, -1]
y_train_log <- with(dbm, yachat[test == 0])


xmat_test <- model.matrix(
  formule,
  data = dbm |>
    dplyr::filter(test == 1)
)[, -1]
# Créer une grille de pénalités
lambda_seq <- seq(from = 0.01, to = 5, by = 0.01)
cv_lasso_lm <- glmnet::cv.glmnet(
  # Attention: la fonction `glmnet` prend une matrice de modèle
  # et un vecteur de réponses
  x = xmat_train_lm,
  y = y_train_lm,
  alpha = 1, # garder cette valeur fixe à un pour le lasso
  lambda = lambda_seq
)
# Pénalité qui minimise l'EQM de validation croisée
lambopt_lm <- cv_lasso_lm$lambda.min #ou cv_output$lambda.1se
lasso_lm <-
  glmnet::glmnet(
    x = xmat_train_lm,
    y = y_train_lm,
    alpha = 1,
    lambda = lambopt_lm
  )

pred_ymontant_lasso <- predict(
  lasso_lm, # modèle duquel prédire
  s = lambopt_lm, # valeur de la pénalité optimale
  newx = xmat_test
)
# Validation croisée pour trouver le critère
cvfit_log <- glmnet::cv.glmnet(
  x = xmat_train_log,
  y = y_train_log,
  family = "binomial"
)
lambda_opt_log <- cvfit_log$lambda.min
# Le critère par défaut est la déviance (-2ll)
# Ajuster modèle avec pénalisation
lasso_log <- glmnet::glmnet(
  x = xmat_train_log,
  y = y_train_log,
  family = "binomial",
  lambda = lambda_opt_log
)
# Prédire sur l'échantillon test (probabilités)
probs_lasso <- predict(
  lasso_log,
  newx = xmat_test,
  s = lambda_opt_log,
  type = "resp"
)
# Trouver les individus avec un profit moyen supérieur à 10$
decision <- probs_lasso * pred_ymontant_lasso > 10
# Envoyer échantillon si profit > 10
# Calcul du profit (revenus moins coûts)
lasso_perfo <- sum(dbm$ymontant[dbm$test == 1] * decision, na.rm = TRUE) -
  10 * sum(decision)
lasso_perfo
